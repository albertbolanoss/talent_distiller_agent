1 · Talent Distiller Agent — System Architecture

The orchestration service: a Starlette upload API and a background poller share one process/pod so a file is always processed by the pod that received it. The Coordinator agent (Claude Agent SDK) fans out to the extraction MCP server while a three-point guardrail enforces idempotency against Redis before, during, and after every turn.

  • AI agent orchestration — single coordinator agent, parallel tool fan-out, per-document-type system prompts from one shared code path.
  • Resilience — Redis-backed, field-granular checkpointing; bounded revision retries; partial progress survives crashes and restarts.
  • Microservice boundary — the extraction capability is a separate MCP service, reachable only over the network, independently deployable and scalable.
  • Observability — structured logging at every phase; Kubernetes liveness/readiness probes on /healthz.

2 · MCP Skills Extractor Agents — Sub-Agent Architecture

The extraction microservice: an MCP server (3 interchangeable transports) exposing 4 independent Claude Agent SDK sub-agents, each grounded in this project's own canonical taxonomy and enforcing a strict output contract with bounded self-correction.

  • Specialized sub-agents — one agent per extraction domain, each grounded in its own canonical taxonomy resource instead of a single generic prompt.
  • Resilience — Pydantic-validated output with a bounded self-correction loop on the same session before failing the call outward.
  • Independent scalability — CANDIDATE_SKILL_AGENT_ACTIVE_TOOLS lets any subset of tools run as its own Helm release, scaled separately from the rest.
  • Protocol-first design — the Model Context Protocol is the service boundary itself: any MCP-compliant client can consume these tools, not just this project's coordinator.

3 · End-to-End Sequence (cross-repo)

One complete file-processing cycle across both services, from upload to persisted result — including the two places retries happen: the bounded self-correction loop inside each extraction sub-agent, and the outer revision-budget loop that re-polls only the fields still missing. 

sequenceDiagram
    autonumber
    actor Rec as Recruiter
    participant API as Upload API (Starlette)
    participant Vol as Pod-local volume
    participant Poll as Background Poller
    participant Guard as CoordinatorGuardrail
    participant Redis as Redis checkpoint store
    participant Coord as Coordinator Agent (Claude SDK)
    participant MCP as MCP Server
    participant Sub as Sub-agent (per tool)

    Rec->>API: POST /resume (multipart file)
    API->>Vol: write file to resume_dir
    API-->>Rec: 201 Created

    loop every poll_interval_seconds
        Poll->>Vol: scan resume_dir / job_posting_dir
        Poll->>Guard: pre_execution_hook(file_path)
        Guard->>Redis: get_status, increment revision_number

        alt all mandatory fields already checkpointed
            Guard->>Vol: move file to processed/
        else revision_number exceeds max_revision_number
            Guard->>Vol: move file to failed/
        else extraction work remaining
            Guard-->>Poll: allowed_tools (missing fields only)
            Poll->>Coord: run_coordinator(file_path, allowed_tools)
            Coord->>Coord: Phase 1 - structure raw text into formatted tags
            Coord->>Redis: save_content(formatted text)
            Note over Coord,Guard: every phase logged via labs_agent_lib.get_logger

            par fan-out, same turn, in parallel
                Coord->>MCP: extract_technical_skills(content)
                MCP->>Sub: run grounded sub-agent
                Sub-->>MCP: JSON array
                opt output fails schema validation
                    MCP->>Sub: self-correction turn, bounded retries
                end
                MCP-->>Coord: validated skills JSON
            and
                Coord->>MCP: extract_soft_skills / extract_certifications / extract_languages
                Note over MCP,Sub: identical self-correction pattern, independent per tool
            end

            Guard->>Coord: PreToolUse hook checks each call against Redis state
            Coord->>Redis: save_agent_result(field, json) per completed tool
            Coord->>Guard: post_execution_hook(session_id, stop_reason)
            Guard->>Redis: save_session_and_completion

            alt is_completed
                Guard->>Vol: move file to processed/
            else still missing fields, revision budget remains
                Note over Poll,Redis: file stays in place, retried next cycle for missing fields only
            end
        end
    end
